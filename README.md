## 🌕 Project Overview

**Moon Rabbit**은 달에 정착한 토끼가 농사와 다양한 활동을 통해 재료를 모으고,
떡을 만들어 판매하며 하루하루 살아가는 **생활 · 경제 게임**입니다.

NAN 2026 대회 참가를 준비하며 아이디어를 실제 게임으로 구현해보기 위해 시작했습니다.

게임의 콘셉트와 규칙부터
농사, 인벤토리, 제작, 상점, 집, 날짜 변화 등
**여러 시스템이 서로 연결되는 게임 구조를 직접 설계하고 구현했습니다.**

완성된 게임은 아니지만,

> **하나의 게임 아이디어를 실제로 조작하고 플레이할 수 있는 형태까지 구현해본 프로토타입 프로젝트입니다.**

---

## 🎮 Core Gameplay

게임의 기본 흐름은 다음과 같이 설계했습니다.

```text
씨앗 구매
   ↓
농사
   ↓
밀 수확
   ↓
떡 제작
   ↓
판매 또는 보관
   ↓
수익 획득
   ↓
다음 날
```

단순히 기능을 각각 구현하는 것보다
**각 시스템의 결과가 다음 행동으로 이어지는 게임 루프를 만드는 것**에 중점을 두었습니다.

---

## 🌱 Farming System

농장에는 여러 개의 밭이 존재하며
플레이어가 직접 밭 근처로 이동해 상호작용할 수 있습니다.

### 구현 내용

* 씨앗 심기
* 작물 성장 시간 관리
* 성장 상태 변화
* 수확 가능한 밭 표시
* 밀 수확
* 수확 결과 인벤토리 반영

밭은 각각 별도의 상태를 가지며

```text
Empty → Growing → Ready
```

순서로 변화하도록 구현했습니다.

---

## 🎒 Inventory System

획득한 아이템을 관리하기 위한
**슬롯 기반 인벤토리 시스템**을 구현했습니다.

### 구현 내용

* 15칸 인벤토리
* 아이템 종류 및 개수 관리
* 동일 아이템 수량 누적
* 마우스를 이용한 아이템 이동
* 슬롯 간 아이템 위치 변경
* 아이템 정보 표시
* 아이템 버리기
* 다른 시스템과의 아이템 데이터 연동

단순한 화면 표시가 아니라
농장, 떡방앗간, 냉장고, 상점이 동일한 아이템 데이터를 사용하도록 구성했습니다.

---

## 🍡 Rice Cake Mill

수확한 밀을 실제 상품으로 만드는
**떡 제작 시스템**을 구현했습니다.

플레이어가 떡방앗간에 들어가면
인벤토리의 재료를 제작 슬롯으로 옮길 수 있습니다.

```text
밀
 ↓
재료 투입
 ↓
제작 진행
 ↓
기본 떡 완성
 ↓
인벤토리 획득
```

### 구현 내용

* 재료 투입 슬롯
* 제작 결과 슬롯
* 제작 시간
* 진행 상태 표시
* 인벤토리와 제작 시스템 연동
* 완성된 떡 회수

이를 통해 **수집 → 제작 → 판매**로 이어지는 기본 경제 루프를 구현했습니다.

## 🏪 Shop System

게임 내 상점을 하나의 기능으로 만들지 않고
목적에 따라 여러 카테고리로 구분했습니다.

### 🛠 도구 상점

생활 활동에 필요한 도구 구매

### 🌱 씨앗 상점

농사에 필요한 씨앗 구매

### 🍡 떡 상점

플레이어가 제작한 떡 판매

### 🏠 집 상점

냉장고와 자물쇠 등 생활 관련 아이템 구매

상품마다 가격, 구매 가능 여부, 판매 가능 여부 등을 별도로 관리하며
일부 아이템에는 **집 레벨에 따른 구매 조건**도 적용했습니다.

---

## 🏠 House System

필드에 있는 집은 단순한 오브젝트가 아니라
직접 들어갈 수 있는 **별도의 실내 공간**으로 구현했습니다.

### 구현 내용

* 외부 ↔ 집 내부 이동
* 실내 전용 상호작용
* 침대
* 냉장고
* 가구 배치
* 가구 이동

특히 가구는 고정된 배경이 아니라
플레이어가 직접 들어서 위치를 옮길 수 있도록 만들었습니다.

```text
SPACE 짧게 누르기 → 가구 사용
SPACE 길게 누르기 → 가구 들어올리기
SPACE 다시 누르기 → 가구 내려놓기
```

하나의 입력 키에서 여러 행동이 충돌하지 않도록
입력 시간을 구분해 상호작용을 처리했습니다.

---

## ❄️ Refrigerator System

제작한 떡을 보관하기 위한
**냉장고 시스템**을 구현했습니다.

플레이어는 인벤토리의 떡을 냉장고로 이동시켜 보관할 수 있으며,
냉장고 역시 별도의 슬롯 데이터를 가지고 있습니다.

### 구현 내용

* 인벤토리 ↔ 냉장고 아이템 이동
* 냉장고 보관 슬롯
* 최대 보관량
* 냉장고 레벨에 따른 용량 차이
* 떡 보관 여부 관리

냉장고는 단순한 창고가 아니라
다음 날 시스템과 연결되도록 설계했습니다.

## 🌙 Day & Sleep System

게임에 하루의 흐름을 만들기 위해
**날짜와 수면 시스템**을 구현했습니다.

플레이어가 집의 침대에서 잠을 자면
수면 진행 화면이 나타나고 일정 시간이 지난 뒤 다음 날로 넘어갑니다.

### 수면 과정

```text
침대 상호작용
    ↓
수면 시작
    ↓
화면 암전
    ↓
수면 진행 표시
    ↓
다음 날
```

HUD의 날짜도 함께 변경되며
하루가 지나면서 다른 게임 시스템에도 변화가 발생합니다.

## 🥀 Food Spoilage System

떡 보관에 의미를 부여하기 위해
**냉장고에 넣지 않은 떡은 다음 날 상하도록 구현했습니다.**

```text
오늘 제작한 떡
       ↓
 ┌──────────────┐
 │              │
판매          냉장고 보관
 │              │
수익           보존
 │
보관하지 않고 다음 날
 │
상한 떡
```

이를 통해 플레이어가

**바로 판매할 것인지 / 보관할 것인지**

선택할 수 있도록 게임 시스템을 연결했습니다.

## 💡 Game Design

구현과 함께 게임 전체 구조도 직접 기획했습니다.

초기 기획에서는 농사뿐만 아니라

* 벌목
* 낚시
* 수렵
* 채광
* 던전

등의 생활 콘텐츠를 확장하고,

각 활동에서 획득한 재료를 기본 떡과 조합하여
새로운 떡을 만드는 구조를 설계했습니다.

예를 들어,

```text
기본 떡 + 목재   → 갈색 떡
기본 떡 + 물고기 → 파랑 떡
기본 떡 + 고기   → 빨강 떡
기본 떡 + 금가루 → 노랑 떡
```

처럼 생활 활동과 제작 시스템을 연결하고자 했습니다.

또한 떡의 가격 변화, 집 업그레이드, 냉장고, 자물쇠, 늑대 습격 등
플레이어가 자원을 어떻게 사용할지 고민하게 만드는 경제 요소도 함께 설계했습니다.

> 해당 요소 중 일부는 게임 기획 단계까지 진행되었으며,
> 현재 프로토타입에는 핵심 플레이 시스템을 중심으로 구현되어 있습니다.

## 🧩 Development Status

**Status : Playable Prototype**

이 프로젝트는 완성된 게임이 아니라
NAN 2026 대회를 준비하며 제작한 **플레이 가능한 프로토타입**입니다.

농사, 인벤토리, 제작, 판매, 집, 냉장고, 날짜 변화 등
게임의 핵심 시스템을 구현한 뒤 **월드와 콘텐츠를 확장하는 단계까지 개발을 진행했습니다.**

맵 확장 작업을 진행하던 과정에서 프로젝트 개발을 마무리하여
일부 월드와 콘텐츠는 완성되지 않은 상태입니다.

하지만 아이디어 단계에서 끝내지 않고,

```text
게임 기획
   ↓
게임 규칙 설계
   ↓
UI 설계
   ↓
시스템 구현
   ↓
시스템 간 데이터 연결
   ↓
플레이 가능한 프로토타입
```

까지 직접 만들어본 프로젝트라는 점에 의미를 두고 있습니다.

## 🧠 What I Learned

처음에는 게임을 만드는 일이
캐릭터를 움직이고 기능을 하나씩 추가하는 것이라고 생각했습니다.

하지만 실제로 구현하면서
각 기능이 서로 독립적으로 존재하는 것이 아니라는 점을 경험했습니다.

농사에서 얻은 아이템이 인벤토리로 들어오고,
그 아이템이 제작 시스템의 재료가 되고,
완성된 상품은 다시 판매와 보관 시스템으로 연결되어야 했습니다.

또한 플레이어 입력, UI 상태, 아이템 데이터, 날짜 변화 등
여러 시스템이 동시에 동작할 때 발생하는 문제를 직접 수정하며

**하나의 서비스를 구성하는 기능들을 서로 연결하는 과정**을 경험할 수 있었습니다.

무엇보다

> **머릿속의 게임 아이디어를 실제로 움직이고 플레이할 수 있는 프로그램으로 만들어본 경험**

이라는 점에서 의미가 있었던 프로젝트입니다.
