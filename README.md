## 🌕 Project Overview

**Moon Rabbit**은 달에 정착한 토끼가 농사를 짓고 떡을 만들어 판매하며,  
매일 증가하는 집세를 감당해 최대한 오래 살아남는 **생활 · 생존 · 경제 게임**입니다.

NAN 2026을 준비하며 게임의 콘셉트와 규칙부터 직접 기획하고,  
이를 실제로 조작하고 플레이할 수 있는 웹 게임으로 구현했습니다.

처음에는 농사 외에도 **벌목, 낚시, 수렵, 채광, 던전 탐험** 등  
다양한 생활 활동을 통해 재료를 모으고,  
이를 떡 제작 시스템과 연결하는 더 큰 규모의 게임을 기획했습니다.

실제 개발에서는 그중 핵심이 되는

> **농사 → 제작 → 판매·보관 → 하루 정산 → 다음 날**

의 흐름을 우선 구현하고,  
인벤토리, 상점, 냉장고, 집세, 떡 시세, 야간 이벤트 등  
여러 시스템이 서로 연결되도록 구성했습니다.

> **완성된 상용 게임은 아니지만, 하나의 게임 아이디어를 실제로 플레이 가능한 형태까지 구현한 프로토타입 프로젝트입니다.**

## 🎯 Game Goal

게임의 목표는 **매일 부과되는 집세를 내면서 최대한 오래 생존하는 것**입니다.

플레이어는 제한된 시간과 자원을 활용해 떡을 생산하고 판매해야 합니다.

하루가 끝나면 집세가 부과되고,  
보유한 돈으로 집세를 낼 수 없으면 게임이 종료됩니다.

플레이어는 매일 다음과 같은 선택을 하게 됩니다.

- 생산한 떡을 지금 판매할 것인가
- 가격 상승을 기대하며 냉장고에 보관할 것인가
- 새로운 재료를 구매해 더 비싼 떡을 제작할 것인가
- 다음 날 집세를 위해 현금을 남겨둘 것인가

---

## 🎮 Core Gameplay

게임의 기본 흐름은 다음과 같습니다.

```text
씨앗 구매
   ↓
농사
   ↓
밀 수확
   ↓
기본 떡 제작
   ↓
색깔 떡 제작
   ↓
판매 / 냉장 보관
   ↓
하루 종료
   ↓
야간 이벤트 · 집세 정산
   ↓
다음 날
   ↓
새로운 떡 시세
```

단순히 기능을 각각 구현하는 것보다,

**앞 단계의 결과가 다음 시스템의 입력이 되도록 하나의 게임 루프로 연결하는 것**

에 중점을 두었습니다.

# ✅ Implemented Features

## 🌱 Farming System

플레이어가 직접 농장에 들어가  
각 밭과 상호작용할 수 있도록 구현했습니다.

### 구현 내용

- 씨앗 심기
- 밭별 성장 상태 관리
- 작물 성장 시간 처리
- 성장 상태 표시
- 밀 수확
- 수확 결과 인벤토리 반영

각 밭은 독립적인 상태를 가지며

```text
Empty → Growing → Ready
```

순서로 변화합니다.

농장 전체가 한 번에 바뀌는 방식이 아니라,  
각 밭이 자신의 성장 시간과 상태를 별도로 관리하도록 구성했습니다.

---

## 🎒 Inventory System

획득한 아이템을 관리하기 위한  
**15칸 슬롯 기반 인벤토리 시스템**을 구현했습니다.

### 구현 내용

- 아이템 종류 및 수량 관리
- 동일 아이템 수량 누적
- 슬롯 간 아이템 이동
- 마우스를 이용한 아이템 이동
- 아이템 정보 툴팁
- 아이템 삭제
- 하단 핫바
- 다른 시스템과 아이템 데이터 공유

단순히 인벤토리 화면에 아이템을 표시하는 데 그치지 않고,

**농장 → 인벤토리 → 방앗간 → 냉장고 → 상점**

으로 동일한 아이템 데이터가 이동하도록 구성했습니다.

---

## 🍡 Rice Cake Crafting

수확한 밀을 이용해 기본 떡을 만들고,  
기본 떡과 다른 재료를 조합해 색깔 떡을 제작할 수 있습니다.

### 기본 떡 제작

```text
밀
 ↓
방앗간 투입
 ↓
제작 진행
 ↓
기본 떡 완성
 ↓
인벤토리 획득
```

### 색깔 떡 제작

초기 기획에서는 각 생활 활동에서 재료를 얻도록 설계했습니다.

```text
기본 떡 + 금가루   → 노랑 달 떡
기본 떡 + 목재     → 갈색 달 떡
기본 떡 + 물고기   → 파랑 달 떡
기본 떡 + 고기     → 빨강 달 떡
기본 떡 + 슬라임   → 초록 달 떡
기본 떡 + 전설재료 → 빛나는 떡
```

현재 프로토타입에서는 생활 활동 전체를 구현하지 못했기 때문에,  
**상점에서 제작 재료를 구매해 색깔 떡 제작 흐름을 체험할 수 있도록 범위를 조정했습니다.**

## 🏪 Shop System

상점은 하나의 화면에 모든 상품을 배치하지 않고  
목적에 따라 카테고리를 구분했습니다.

### 🛠 도구 상점
생활 활동에 사용할 도구를 구매할 수 있습니다.

### 🌱 씨앗 상점
농사에 사용할 씨앗과  
색깔 떡 제작에 필요한 재료를 구매할 수 있습니다.

### 🍡 떡 상점
플레이어가 제작한 떡을 판매할 수 있습니다.

### 🏠 집 상점
냉장고와 자물쇠 등  
집과 관련된 아이템을 구매하는 구조로 설계했습니다.

상품마다 가격과 구매·판매 가능 여부를 따로 관리하고,  
일부 상품에는 집 레벨에 따른 구매 조건도 적용했습니다.

## 📈 Rice Cake Market

초기 기획에서 중요하게 생각했던 요소 중 하나는  
**떡 가격의 변동**이었습니다.

기본 떡의 가격은 고정되어 있지만  
색깔 떡의 가격은 하루가 바뀔 때마다 달라집니다.

```text
기본 떡 → 가격 고정

색깔 떡 → 매일 -30% ~ +30% 가격 변동
```

이를 통해 플레이어는

**오늘 판매할지 / 냉장고에 보관하고 가격 상승을 기다릴지**

선택할 수 있습니다.

---

## 🏠 House System

필드의 집은 단순한 배경 이미지가 아니라  
플레이어가 실제로 들어갈 수 있는 **별도의 실내 공간**으로 구현했습니다.

### 구현 내용

- 외부 ↔ 집 내부 이동
- 침대
- 냉장고
- 창고 공간
- 실내 상호작용
- 가구 이동

특히 가구는 고정된 배경이 아니라  
플레이어가 직접 들어서 이동할 수 있도록 만들었습니다.

```text
SPACE 짧게 누르기 → 사용
SPACE 길게 누르기 → 가구 들어올리기
SPACE 다시 누르기 → 내려놓기
```

하나의 키로 여러 행동을 처리해야 했기 때문에  
입력 시간을 구분해 동작이 충돌하지 않도록 구현했습니다.

## ❄️ Refrigerator System

냉장고는 완성한 떡을  
다음 날까지 보관하기 위한 공간입니다.

### 구현 내용

- 인벤토리 ↔ 냉장고 아이템 이동
- 냉장고 전용 슬롯
- 떡 종류만 보관 가능
- 최대 보관량 관리
- 냉장고 레벨 구조
- 하루 변화 시스템과 연동

냉장고를 단순한 추가 인벤토리가 아니라  
게임의 경제 시스템과 연결했습니다.

## 🥀 Food Spoilage System

냉장고에 보관하지 않은 떡은  
하루가 지나면 **상한 떡**으로 변경됩니다.

상한 떡은 더 이상 판매할 수 없습니다.

```text
오늘 만든 떡
       ↓
 ┌──────────────┐
 │              │
판매          냉장고 보관
 │              │
현금 확보       보존
 │
보관하지 않고 하루 종료
 │
상한 떡
```

이를 통해 플레이어가 단순히 모든 떡을 쌓아두는 것이 아니라

**지금 판매할지 / 보관할지**

선택하도록 만들었습니다.

## 🌙 Day & Sleep System

게임에는 현실 시간과 별개의  
하루 흐름이 존재합니다.

게임 시간은

```text
08:00 → 23:00
```

으로 진행됩니다.

플레이어가 집의 침대에서 잠을 자거나  
하루가 끝나면 다음 날로 넘어갑니다.

### 구현 내용

- 게임 시간
- 날짜 변화
- 수면 진행
- 화면 암전
- 다음 날 처리
- 떡 시세 변경
- 떡 상함 처리
- 야간 이벤트
- 집세 정산

## 💰 Rent & Game Over

게임의 핵심 생존 요소는 **집세**입니다.

첫날 집세는 낮게 시작하지만  
날짜가 지날수록 계속 증가합니다.

```text
하루 플레이
   ↓
집세 정산
   ↓
다음 날 집세 증가
```

집세를 낸 뒤 보유금이 부족하면  
달토끼가 집에서 쫓겨나면서 게임이 종료됩니다.

단순히 돈을 많이 모으는 것이 아니라  
**앞으로 지불해야 할 비용까지 고려하도록 만든 경제 요소**입니다.

## 🐺 Wolf Event

초기 기획에서 떡을 장기간 보관할 때의 위험 요소로  
**늑대 습격**을 설계했습니다.

밤마다 일정 확률로 늑대가 찾아오며,  
방어 수단이 없다면 냉장고에 보관된 떡 일부를 잃을 수 있습니다.

자물쇠 종류에 따라 방어와 소모 방식도 다르게 설계했습니다.

현재 코드에는 늑대 습격과 자물쇠 처리 로직까지 구현되어 있지만,  
**집 업그레이드 시스템이 완성되지 않아 현재 공개 버전에서는 자물쇠 성장 흐름 전체를 플레이하기에는 제한이 있습니다.**

# 🗺 World Expansion Attempt

개발 후반에는 현재 마을을 넘어  
더 넓은 달 표면을 탐험할 수 있도록  
**3 × 3 형태의 월드 확장**을 시도했습니다.

기존 게임 화면은

```text
1280 × 720
```

이었고 이를 기준으로

```text
1280 × 720 × 3 × 3
→ 3840 × 2160
```

규모의 월드를 구성했습니다.

확장 월드에서는  
플레이어의 움직임을 따라 카메라가 이동하도록  
**플레이어 추적 카메라**도 구현했습니다.

하지만 실제 플레이에 적용하면서  
단순히 맵의 크기와 좌표만 늘린다고  
자연스러운 게임 월드가 만들어지는 것은 아니라는 점을 경험했습니다.

### 발생한 문제

- 기존 마을과 확장 영역의 이미지 비율 차이
- 배경 이미지 사이의 연결 문제
- 확장 과정에서 기존 마을이 한눈에 보이지 않는 문제
- 카메라 이동과 기존 상호작용 좌표의 정합성
- 넓어진 공간에 배치할 실제 콘텐츠 부족
- 기능 추가가 오히려 기존 화면의 완성도를 낮추는 문제

여러 방식으로 배경을 확장해보았지만,  
완성되지 않은 영역을 억지로 보여주는 것보다  
현재 구현된 게임의 완성도를 안정적으로 보여주는 것이 더 중요하다고 판단했습니다.

따라서 최종 공개 버전에서는

- 기존 1280 × 720 마을 유지
- 카메라 고정
- 플레이어의 마을 밖 이동 제한
- 가장자리 접근 시 `🚧 이 지역은 준비 중입니다` 표시

방식으로 범위를 다시 정리했습니다.

확장 월드와 플레이어 추적 카메라 코드는  
향후 확장을 위해 코드에 남겨두었습니다.

# 🎨 Visual Assets & Limitations

이번 프로젝트의 시각 요소는  
직접 그린 정식 아트 에셋이 아니라,  
**AI 이미지 생성 도구를 활용해 제작한 배경 및 오브젝트 이미지**를 중심으로 구성했습니다.

이 방식은 제한된 시간 안에  
게임 분위기와 콘셉트를 빠르게 시각화하는 데에는 도움이 되었지만,  
다음과 같은 한계도 분명히 존재했습니다.

### 한계

- 오브젝트 간 스타일 완전 일치의 어려움
- 월드 확장 시 배경 연결의 부자연스러움
- 내부 오브젝트 에셋의 부족
- 수정과 재사용의 제약

특히 집 내부의 일부 오브젝트는  
최종 아트 에셋 대신 **임시 박스형 UI 요소**로 남아 있습니다.

예를 들어,

- 침대
- 창고

등은 기능과 상호작용 구조를 먼저 구현한 뒤,  
시각적인 마감은 후순위로 두었습니다.

즉 이 프로젝트에서는  
**시각 자산의 완성도보다 플레이 가능한 구조와 시스템 구현을 우선한 선택**을 했습니다.

# 💡 Original Game Design

초기 기획의 Moon Rabbit은  
현재 프로토타입보다 훨씬 큰 규모의 게임이었습니다.

농사 외에도 다음과 같은 생활 활동을 설계했습니다.

```text
벌목 → 목재
낚시 → 물고기
채광 → 금가루
수렵 → 고기
던전 → 슬라임
```

각 활동에서 낮은 확률로 희귀 재료를 획득하고,  
기본 떡과 조합해 더 가치 있는 떡을 만드는 구조였습니다.

또한 도구를

```text
나무 → 철 → 금 → 다이아
```

등급으로 강화하면서

- 생활 활동 속도 증가
- 획득 재료 수 증가
- 희귀 재료 획득 확률 증가

등의 성장 요소도 기획했습니다.

집 역시 1~3레벨까지 성장시키고,  
집 레벨에 따라 더 좋은 냉장고와 자물쇠를 사용할 수 있도록 설계했습니다.

# 🧠 What I Learned

처음에는 게임 개발이  
캐릭터를 움직이고 원하는 기능을 하나씩 추가하는 과정이라고 생각했습니다.

하지만 실제로 구현하면서  
가장 어려웠던 부분은 기능 하나를 만드는 것보다  
**여러 시스템의 상태와 데이터를 서로 연결하는 것**이었습니다.

농장에서 수확한 밀은 인벤토리로 들어가고,  
인벤토리의 재료는 방앗간에서 사용되며,  
완성된 떡은 다시 판매와 냉장 보관으로 나뉩니다.

하루가 지나면

- 떡의 가격이 변하고
- 냉장고 밖의 떡이 상하고
- 늑대 이벤트가 발생하며
- 집세가 부과되고
- 그 결과가 다음 날 플레이에 영향을 줍니다.

각각의 기능은 단순했지만  
이 기능들이 동시에 동작하기 시작하면서  
입력 상태, UI 상태, 아이템 데이터, 시간 등  
여러 상태를 함께 관리해야 했습니다.

### 월드 확장을 통해 느낀 한계

개발 후반에는 게임의 완성도를 높이기 위해  
맵을 3 × 3으로 확장하고  
플레이어를 따라다니는 카메라도 구현했습니다.

처음에는 기능을 더 추가하면  
당연히 게임의 완성도가 높아질 것이라고 생각했습니다.

하지만 실제 플레이에서는 반대의 상황도 발생했습니다.

넓어진 공간에 맞는 콘텐츠와 배경이 충분하지 않은 상태에서  
월드만 확장하자 기존에 잘 보이던 마을이 오히려 잘리고,  
배경 이미지의 연결과 좌표 문제도 발생했습니다.

또한 이미지 에셋의 상당 부분을 AI 생성 이미지에 의존하다 보니,  
새로운 공간에 필요한 자산을 일관된 스타일로 계속 확장하는 데에도 한계가 있었습니다.

이 과정에서

> **기능을 많이 구현하는 것과 완성도 높은 결과물을 만드는 것은 항상 같은 의미가 아니라는 것**

을 배웠습니다.

최종적으로는 미완성된 확장 영역을 그대로 보여주기보다  
현재 구현된 마을을 하나의 완성된 플레이 공간으로 정리하고  
확장 지역의 이동을 제한했습니다.

처음 계획했던 모든 기능을 구현하지 못한 것은 이 프로젝트의 한계이지만,  
그 과정에서 **현재 구현 상태를 판단하고 범위를 조정해 실제로 배포 가능한 결과물로 마무리하는 경험**을 할 수 있었습니다.

무엇보다

> **머릿속의 게임 아이디어를 규칙과 시스템으로 설계하고,  
> 실제로 움직이고 플레이할 수 있는 웹 게임으로 만들어본 경험**

이라는 점에서 의미가 있었습니다.
